## 4. Design direction (for the checkpoint; frontend-design skill two-pass applied)

**Subject grounding.** A founder-engineer from Kozhikode, the Malabar pepper coast, who builds "software for work that can't go wrong": audit trails, role scoping, every number with a source. The visual idea: **everything on the site is assembled from small, verifiable pieces.** One persistent WebGL particle system is the only spectacle; it forms his portrait on Home and becomes something else on every page. Everything around it is quiet, editorial, ledger-like.

**Tokens**
- Colour (dark default): `--ink-900 #0C1A1D` (deep sea-ink base, teal-tinted, deliberately not near-black and not Txtudio navy), `--ink-800 #12272B` (raised surfaces), `--ink-700 #1C3A40` (rules), `--fg #EEF3F1`, `--fg-soft #A9B8B4`. Light mode: `--paper #F2F4F3` (cool monsoon white, not cream), `--paper-raised #FFFFFF`, `--rule #D5DDDA`, `--fg #10201F`, `--fg-soft #4C5F5B`. Accent "pepper gold": `#E0A33B` on dark, `#8F6412` on light (AA against both bases); used only for the primary CTA, link underlines, focus rings and the active nav mark. Particles: warm-white light points on dark; ink-black "grains" on light (sprite with a soft specular so they read as grains, not squares). No gradients as decoration, no glassmorphism.
- Type: **Archivo** (variable, width axis 62–125 + weight) as the single UI/display family, with the width axis carrying meaning: Expanded is used for the name only; page titles and H2 at normal width, weight 500; ledger rows (year, role, stack, outcome) in SemiCondensed with tabular figures so dense data reads like a register; body/UI at normal width. **Newsreader** (variable, optical size) for long-form body on Writing and case studies at 18px with a 62–70ch measure and generous leading. Code: system monospace stack (no third font). Scale 1.25 from 16px: 16/20/25/31/39/49/61/76; hero name `clamp(2.6rem, 9vw, 7.5rem)` at weight 500, Expanded, tracking −0.02em. Sentence case headings; no all-caps eyebrows; no middle-dot meta strings; no arrows glued to link text. Fonts load through Astro's Fonts API (fontsource provider); step 0 verifies that the delivered Archivo file carries the `wdth` axis, otherwise switch to `fontProviders.local()` with the OFL variable TTF.
- Layout: left-aligned, 12-column grid, 1200px content max, 16px gutters on phones. Fixed top bar: small Expanded wordmark "Kiran K S" + 7 nav items + theme toggle + "Pause motion" (collapses to a full-screen menu on phones with the particle layer visible behind). Rhythm on an 8px base; sections separated by space and one hairline rule, not cards. **Home is one ledger** after the hero: group "Companies" (two rows: Txtudio, Lofritex) then group "Selected work" (four rows), then three writing titles; profile links live in the footer only. This replaces the generic hero → strip → cards → posts → profiles stack while keeping the ventures-first intent. The Work index is the full ledger (year, name, role, stack, outcome); a row expands on click/hover to a preview (user-triggered motion only). Case studies are long-form editorial with one full-bleed 3D moment each. Light mode caps the particle density one tier lower than dark (dark grains over text read as dirt).
- Motion language: Lenis smooth scroll (duration ~1.1s, respects reduced-motion); GSAP ScrollTrigger for the single scroll-bound moment per page; Astro `<ClientRouter />` view transitions with the nav and the WebGL canvas marked `transition:persist` so navigation never reloads the scene; on `astro:before-swap` the particle system morphs to the next page's target over ~1.2s (ease: expo.out) while the page content cross-fades with a 40px vertical drift. Text reveals once (SplitText on H1/H2 only). Reduced motion or "Pause motion": the outline stays drawn with a static grain poster behind it, no particle animation, instant transitions.

Astro 7 specifics that shape the code (from the stack research, verify against docs.astro.build at build start): content collections in `src/content.config.ts` with `glob()` loaders and `z` from `astro/zod` (Zod 4); Markdown/MDX run through Sätteri by default (install `@astrojs/markdown-remark` 7.3.5 + `markdown.processor: unified()` only if remark/rehype plugins are needed); the Rust compiler rejects unclosed tags and `compressHTML` defaults to `'jsx'` (set `compressHTML: true` so split-text markup keeps its spaces); Fonts API is stable (`fonts: [{ name: 'Archivo', cssVariable: '--font-display', provider: fontProviders.fontsource(), … }]` + `<Font cssVariable preload />` from `astro:assets`; no @fontsource packages needed); `<ClientRouter />` from `astro:transitions` with string lifecycle events (`astro:before-swap`, `astro:after-swap`, `astro:page-load`) and `transition:persist`; shaders imported as strings with Vite's `?raw` (no GLSL plugin; Vite 8/Rolldown); `postprocessing` is NOT used (peer three < 0.187); `@astrojs/cloudflare` is NOT needed (static). `<canvas>` is never an LCP candidate, so the hero's LCP element is the H1 text block; the inline SVG outline is the first visual frame, and the canvas cross-fades in after its first rendered frame (details under "Key mechanics").

Key mechanics (incorporating the independent critique):
- **Persistent canvas across routes**: the canvas wrapper in `Base.astro` carries `transition:persist="scene" transition:name="scene" transition:animate="none"` (so the view-transition snapshot never ghosts a frozen copy over the live scene) and no `overflow:hidden` ancestor. The Three.js engine is a singleton booted once from the layout's bundled module; nothing per page ever creates a renderer. `bridge.ts` listens to `astro:before-swap` and reads the destination from `event.to.pathname` / `event.newDocument.body.dataset.scene` (history is not updated yet at that point, so `location` would target the old page), then `particles.morphTo(target, 1.2s)`; `astro:after-swap` updates `aria-current` in the persisted nav, snaps the scroll-bound progress uniform to the restored scroll position, calls `lenis.scrollTo(target, { immediate: true })`, then `ScrollTrigger.refresh()` after `document.fonts.ready`.
- **Theme across swaps**: ClientRouter's root-attribute swap would reset `data-theme`; `astro:before-swap` copies `data-theme`/`data-motion` from the current `<html>` onto `event.newDocument.documentElement`. The inline theme bootstrap is hashed via Astro `security.csp`.
- **One per-page motion registry**: bundled page scripts run once per session under ClientRouter, so no page file registers its own listeners. `motion/transitions.ts` is the single `astro:page-load` handler: it builds reveals/pins from `[data-reveal]`/`[data-pin]` markup inside `gsap.matchMedia()` (with a reduced-motion branch), reverts on `astro:before-swap`. SplitText initial hidden states are gated behind `html.js-motion`, so a failed script never hides an H1.
- **Hero first frame and LCP**: the H1 text block is the LCP element; the inline SVG outline is server-rendered (not an LCP candidate, no image poster in the default path) inside the same reserved `aspect-ratio` box as the canvas, so CLS stays ≤ 0.02. three.js and the tier-specific target `.bin` are dynamically imported after `astro:page-load`/idle, never in the critical path; the canvas cross-fades in on its first rendered frame; particles start as a loose cloud and stream into the already-drawn outline (no finished-portrait → cloud → portrait flash). Reduced motion, WebGL failure or tier "none" → the outline stays fully drawn and a static grain poster (`<img>` per theme, generated offline) fades in behind it.
- **Particle data**: ONE pipeline, `scripts/preprocess/portrait.py` (rembg birefnet-portrait cut-out → CLAHE → luminance + edges → importance sampling → x, y, z, colour, seed → binaries at 8k/24k/60k + the two static posters). No sharp-based JS sampler.
- **Adaptive quality**: tier A (60k points, DPR ≤ 2, GPGPU HalfFloat spring physics), B (24k, DPR 1.5), C (8k, DPR 1, `antialias:false`); light theme caps at B. Tier from detect-gpu + `deviceMemory`/`hardwareConcurrency` + a 1s rAF probe. Render loop pauses when the canvas is off-screen or the tab hidden, and when the user hits "Pause motion". `powerPreference: 'default'`; on iOS resize only on width change or > 15% height change (URL-bar collapse) and size from a `dvh` box; `webglcontextlost` → poster state.
- **SEO head**: one `<Seo>` component: title (≤60 chars), description (≤155), canonical, OG/Twitter (per-page OG image), `lang="en-IN"`, RSS autodiscovery, theme-color per theme. One `<JsonLd>` emitting a single `@graph` from `person.ts`: `Person @id #person` (name, alternateName, image, jobTitle "Founder & CEO", address Kozhikode/Kerala/IN, alumniOf CEV, worksFor/founder-of Txtudio + Lofritex Organizations, memberOf IEEE CS, knowsAbout, sameAs GitHub + LinkedIn), `WebSite`, `ProfilePage` on `/`, `AboutPage`, `CollectionPage` + `ItemList` on /work /writing /lab, `Article`/`BlogPosting` + `SoftwareSourceCode` on case studies/posts, `ContactPage`, `BreadcrumbList` on inner pages. Never HowTo; no FAQPage.
- **Theme**: `[data-theme]` tokens; inline head script reads localStorage/system before paint; toggle in nav; particles switch sprite/colour uniforms on theme change.
- **Writing**: MDX with Shiki code blocks, reading time, updated dates, author box, related case studies; `/rss.xml` via @astrojs/rss.
- **Résumé**: `/resume` route renders from `person.ts` with `print.css` (A4, 1–2 pages); `scripts/resume-pdf.mjs` produces the PDF; Experience page links it.
- **OG images**: `src/pages/og/[...slug].png.ts` with `getStaticPaths` over all routes (≈ 16), satori 0.63.2 with raw Archivo TTF buffers from `src/assets/fonts` (the Fonts API output is not addressable at build), rasterised by sharp; excluded from the sitemap.
- **Cloudflare specifics**: Workers static assets with `html_handling: 'drop-trailing-slash'` + `build.format: 'file'` so `/about` is canonical and `/about/` 308s to it; `_headers` for HSTS / nosniff / Referrer-Policy / Permissions-Policy plus a host-scoped `X-Robots-Tag: noindex` for preview hosts (CSP comes from Astro `security.csp`, not `_headers`); `_redirects` (www → apex); `404.html` served with status 404 via `not_found_handling`; build command `pnpm build`, output `dist`, Node 24 via `.nvmrc`.
